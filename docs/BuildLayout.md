# 빌드와 테스트 리소스

모듈·명령 도구·테스트 컴파일 결과는 `build/`에 둔다. 프로토콜 시험에 필요한 rclone, Python 환경과 관련 자료는 `resources/dependencies/protocol/`에 둔다. Windows SMB 시험의 다운로드 원본과 NuGet 자료는 `resources/dependencies/smb-fixture/`에 두고 컴파일된 테스트 fixture만 `build/`에 둔다. 이를 명시적으로 준비하거나 테스트할 때 필요한 네트워크 접근과 툴체인은 해당 작업의 요구사항이다.

각 파일·TLS 테스트는 `resources/t/`에 서로 겹치지 않는 임시 디렉터리를 만들고 테스트 종료 또는 실패 후 제거한다. 숨김 상위 경로를 자동 프리뷰에서 제외하는 파일 제공자 계약에 맞춰 일반 파일의 프리뷰를 검증하며, 테스트 내부의 숨김·제어 파일 제한은 별도로 유지한다. 해당 테스트의 인증서와 개인 키도 구성 단계가 아닌 시험 시점에 생성해 같은 공간에서 제거한다. FTP fixture는 필요한 Python 어댑터와 네이티브 파일 제공 라이브러리를 해당 시험 공간에 준비한다. 경로는 프로젝트 리소스 아래로 제한하며 기존 파일을 덮어쓰지 않는다. 환경 변수 `IIWEBSERVER_TEST_PROVIDER_PYTHON_DIR`로 테스트 전용 iiFileProvider Python 어댑터 경로를 지정할 수 있다.

프로세스가 강제 종료되면 정리 코드가 실행되지 않을 수 있으므로 남은 작업 공간은 사용 여부를 확인한 뒤 정리한다. Unix의 최상위 `build/` 구성은 기존 `protocol-deps`와 `graphql-dependencies` 경로를 해당 리소스에 연결한다. 기존 파일과 다른 링크는 덮어쓰지 않는다. Windows에서는 자동 호환 링크를 만들지 않으므로 리소스 경로를 직접 지정한다. 옮겨진 Python 환경의 도구 경로가 유효하지 않으면 환경을 다시 만들어야 한다.

`install.sh`는 기본적으로 로컬 서버를 띄우지 않는 계약 검사를 수행한다. 실제 HTTP·릴레이·FTP 등 서버나 프로세스를 시작하는 전체 CTest 검사는 명시적으로 `IIWEBSERVER_RUN_INTEGRATION_TESTS=1`을 지정하거나 별도로 `ctest`를 실행할 때 수행한다. 각 테스트의 기존 제한 시간은 유지된다. 설치 소비자 검사는 사용 중인 빌드가 없을 때 `build/`를 소비자 구성으로 교체한 후 수행하고 모듈 빌드를 복원한다.

이전 `build/`의 사용자 데이터나 개인 키를 정리할 때에는 먼저 사용 여부를 확인하고 필요 자료는 `resources/.recovery/`에 보존한다. 예전 다중 빌드와 로그 경로는 현재 검증 결과가 아닌 이력이다. 로컬 데이터와 테스트 작업 공간은 Git에 추가하지 않는다.

현재 macOS 빌드에서 선택된 Homebrew OpenSSL 4 라이브러리는 macOS 27용이다. 이 환경의 빌드 성공만으로 macOS 12 등 이전 운영체제 지원을 보장하지 않는다. 더 낮은 배포 대상을 요구하는 제품은 그 대상과 호환되는 OpenSSL을 별도로 준비해 다시 빌드하고 검증해야 한다.
